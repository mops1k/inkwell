# AGENTS.md — xteink-shelf

## Что это за проект

Форк **Paperio Reader 2.3.0** (`Kapfilm/Paperio-Reader`, коммит `d0eb931`, тег `base-2.3.0`) под устройство **Xteink X3**.
Задача проекта — добавить «книжную полку» в стиле Android-приложения BookShelf, не ломая существующую прошивку:
индексирование библиотеки, сетка обложек, полки и правила, serverless-синхронизация с Android по Wi-Fi, свой канал OTA.

Правила разработки самого форка — в `.skills/SKILL.md` (читать до любых правок). Этот файл их дополняет, не заменяет.

## Устройство и потолки

- MCU ESP32-C3: ~380–400 КБ SRAM, **PSRAM нет**, один кадр 792×528 в 1 бит = 52 272 байта.
- Экран E-Ink, 4 градации серого (~259 PPI), **тача нет** — управление только кнопками:
  Up/Down (боковые), Left/Right/Confirm/Back (передние, переназначаемые), Power.
- Флеш 16 МБ: `app0`/`app1` по 6,25 МБ, `spiffs` 3,375 МБ, `coredump`. Обновление с SD-карты и по OTA.
- Целевой размер библиотеки — **~100 книг**, индекс помещается в RAM (~20–40 КБ), потоковый индекс не нужен.

## Поддерживаемые форматы (по коду, не по названию файла)

- **EPUB** `.epub`; **FB2** `.fb2`, `.fb2.zip` и обычный `.zip` с FB2 внутри (тип определять по содержимому — `detectBookArchiveType`); **TXT** `.txt`; **Markdown** `.md`; **XTC / XTC-H** `.xtc`, `.xtch`.
- Изображения для обложек и заставок: `.jpg/.jpeg/.png/.bmp/.gif`.
- Кодировки FB2: UTF-8, Windows-1251, KOI8-R.
- Новые форматы (MOBI, PDF, CBZ и др.) без отдельного решения не добавляем.

## Архитектурные правила

- Новый код: `src/activities/shelf/` (экранная логика) и `lib/Shelf/` (индекс, обложки, протокол синхронизации).
- Общая логика — один компонент и один вход; копии по экранам и слоям запрещены.
- Обложки — только через существующий конвейер `ReaderActivity::generateThumbBmp()` и файлы `thumb_<W>x<H>.bmp` в кэше книги (`/.crosspoint/...`). Второй формат кэша обложек не вводить.
- Состояние полки — `/.crosspoint/shelf/`, запись атомарная (`.tmp` + `rename`), при повреждении — восстановление, а не падение.
- `BootHealth`, `OtaBootSwitch`, `FirmwareFlasher`, загрузочный путь и `force_update.bin` не менять без задачи Ф6 и соответствующего теста.
- Патчи к upstream — минимальные: новые файлы предпочтительнее, правки существующих точечные, чтобы мержи с Kapfilm не ломались.

## Анти-кирпич — инварианты

1. Писать только в app-слот штатным updater; **никогда** не стирать bootloader, таблицу разделов и factory NVS.
2. Валидация образа до стирания: MCU, magic/структура, board-тег, размер ≤ слот, SHA-256, монотонность версии.
3. Отказ от обновления при низком заряде; атомарная подмена; ограниченные ретраи вместо циклов.
4. OTA — только из нашего канала релизов, не из релизов Kapfilm. Канал задаётся ключом
   `platformio.ini` `[crosspoint] repository` (его `scripts/git_branch.py` превращает в
   `-DCROSSPOINT_GIT_REPOSITORY`), fallback — в `src/network/OtaUpdater.h`. Релиз обязан содержать
   `firmware-manifest.json`: устройство выбирает application по своей плате (`devices`) и сверяет
   SHA-256 из манифеста с потоком до активации слота; без манифеста обновление не ставится.
   Версии остаются 1.x, переход с Paperio Reader 2.3.x — только с SD-карты.

## Проверки

- Host-тесты: `cmake -S test -B build/test && cmake --build build/test && ctest --test-dir build/test --output-on-failure -j`
  (GoogleTest подтягивается FetchContent при первой конфигурации). Перед первой сборкой нужны сгенерированные
  i18n-заголовки: `.venv/bin/python scripts/gen_i18n.py lib/I18n/translations lib/I18n/`.
- Новая логика — с host-тестом; парсеры — с фаззингом; ошибки SD и питания — через fault injection.
- Прошивка: PlatformIO 6.2.0 из `.venv` — `.venv/bin/pio run -e default` (ESP32-C3). Нужен сабмодуль
  `freeink-sdk` (`git submodule update --init --recursive`). Ориентир: образ ~5,16 МБ при слоте 6,25 МБ (78,6 %), RAM 17,1 %.
- Форматирование: `clang-format -i` по `src/**` и `lib/**`.
- Коммиты: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`, `perf:`; без явной просьбы не коммитить и не пушить.
